# T6 FastAPI service Implementation Plan

> Owning task: T6 in `.hermes/plans/2026-10-04_demo-path.md`. Work task by task,
> mark progress here ([ ] todo [~] in progress [x] done), no drift into T7/T8.

Goal: an uploaded shelf photo returns, per reporting category, ours vs tracked
rivals and the share (`POST /count`), the same photo with role-coloured boxes
(`POST /overlay`), and model/version status (`GET /health`).

Architecture: a thin FastAPI layer in `src/face_counter/serving/` (empty
package today) over one `Pipeline` object loaded once at startup:
detector (yolo26l-sku110k, via `training/detector_bakeoff.py` builders) ->
crop naming (T3 DINOv2 matcher + T4 CLIP can/glass, refactored out of
`identification/predict.py`) -> `share.evaluate()` on a single Photo. No new
business logic: the taxonomy, roles and share maths stay in `evaluation/share.py`.

Tech stack: FastAPI, uvicorn, python-multipart (uploads), httpx (TestClient,
dev only). Models as today: ultralytics, transformers, torch (the `analytics`
group).

Decided 2026-10-10 (user): plan T6 now; SKU-level galleries move to T8 /
future work. The demo ships with the identity caveat, not held for it.

---

## Context the implementer needs

- Model quality is NOT demo-grade and the API must not pretend otherwise (T5
  verdict): threshold 0.0625 over-matches grey boxes; 0.7115 (tuned with
  `--include-product-boxes`) misses 88% of named crops. The API reports what
  the pipeline says plus a `caveats` list; it does not fix the model.
- Faces vs objects (`docs/ISSUE_FACES_NOT_OBJECTS.md` s4 "Reporting"): the
  detector finds *units*, not faces. Response fields are named `units`, and
  `caveats` says so. Never call them faces.
- Roles come from `share.Taxonomy.resolve()`: ours / ours_unreported /
  targeted / untargeted; headline share is `scope.share_against` (targeted).
- Categories: `configs/scope.yaml` `categories: [canned_drinks, glass_drinks]`.
- Detector API: `detector_bakeoff.Detector = Callable[[Image], Detections]`,
  `Detections(boxes, scores, labels)`; build with
  `build_yolo26l_sku110k(imgsz=1280, conf=0.25, opts)`, weights path from
  `configs/bakeoff.yaml` (`resolve_weights`). Weights are gitignored (`*.pt`).
- HEIF: `embedder.py` already registers the HEIF opener at import (the T5
  side note is resolved); uploads go through `embedder.load_image`-style
  EXIF transpose + RGB.
- Tests mock every model, the way `tests/test_predict.py` and
  `tests/test_identification.py` already do. This laptop cannot run torch
  convs; real inference runs on hemin only when the user says it is up.

### [x] Task 3: Pipeline object (serving/pipeline.py) — DONE 2026-10-10 (commit efd27ff), REVISED SCOPE

**Decided 2026-10-10 (user, mid-task):** the matcher/share path (T3/T5) is
not demo-safe — 65.3% identity accuracy and the T5 architectural gap mean
it shows plausible-looking wrong numbers. The detector and T4's can/glass
classifier (93.8% acc on gold) both work. So the default `/count` path
drops brand identity entirely: detect -> classify pack type for *every*
crop (not just unmatched ones) -> count per category. No gallery, no
DINOv2, ever, unless a request explicitly asks for it.

- `ServeConfig`: as planned, same env vars/defaults.
- `Pipeline.load(cfg)` builds only the ONNX detector + `reporting.yaml` —
  no gallery, no embedder at startup.
- `Pipeline.run(img, debug=False) -> Result`: detect -> crop -> T4
  `pack_type.pack_types()` on every crop -> count per category
  (`BoxResult(xyxy, pack_type, category, score)`, `Result.categories`,
  `Result.units_detected`). `debug=True` lazily loads the gallery +
  DINOv2 on first use (`_ensure_debug_deps`, cached after) and adds
  `Result.debug: DebugResult | None` (T3 matcher + `share.evaluate`,
  `DebugResult.caveats` naming the 65.3%/T5 numbers explicitly). Default
  response never includes `debug`.
- 5 tests in `tests/test_serving.py`: pack-type counts without debug;
  zero boxes; `debug=False` asserts `gallery.build` is never called;
  `debug=True` wires the matcher + caveats; `ServeConfig.from_env` defaults.

### [x] Task 4: Response schema (serving/schemas.py) — DONE 2026-10-10 (commit 9d5dc0e)

Files: create `src/face_counter/serving/schemas.py`, extend `tests/test_serving.py`
- Pydantic models mirroring `pipeline.Result`/`DebugResult` exactly, not the
  original ours/targeted/share shape:
  `CountResponse`: `units_detected: int`, `categories: dict[str, int]`,
  `boxes: [{xyxy, pack_type, category, score}]`, `model` (detector name,
  pack classifier name, onnx path/sha or version tag), `timings_ms`,
  `caveats: [str]` (static: units are detected products not "faces";

  `DebugResponse`: `boxes: [{xyxy, label, role, similarity}]`,
  `share: {category: {ours, targeted, untargeted, share (null if NaN)}}`,
  `caveats: [str]` (the `DEBUG_CAVEATS` from pipeline.py, verbatim).
- NaN -> null in the debug share (JSON has no NaN). Test that.
- Commit: `✨ feat(serve): /count response schema, debug fields opt-in`.

### [x] Task 5: App and endpoints (serving/app.py) — DONE 2026-10-10 (commit 7b2a923)

Files: create `src/face_counter/serving/app.py`, extend `tests/test_serving.py`
- `create_app(pipeline=None)`: lifespan loads `Pipeline.load(ServeConfig.from_env())`
  unless a pipeline is injected (tests inject a fake).
- `GET /health`: status, detector/classifier names, git sha
  (`git rev-parse` at startup, fallback env `FACE_COUNTER_VERSION`). No
  gallery/debug status here — Task 3's lazy load means it may not exist yet.
- `POST /count` (multipart `file`, optional query/body flag `debug: bool =
  False`): reject non-image / unreadable -> 400; size cap 20 MB -> 413; run
  pipeline in a threadpool (`run_in_threadpool`, inference is blocking);
  return `CountResponse` (debug fields only present when `debug=true` was
  passed AND the caller is authenticated — see Task 5b, debug stays
  internal-only even behind the API key).
- `POST /overlay`: same input, returns `image/jpeg`; boxes coloured by
  **pack type** (canned vs glass — the reliable signal), grey for anything
  below the detector's own confidence display threshold; long side
  downscaled to 1600 px. No role colouring (ours/rival) by default — that
  only applies in a `?debug=true` overlay variant, clearly watermarked
  "EXPERIMENTAL" on the image itself, not just in JSON, so a screenshot
  shared out of context still carries the caveat.
- One `threading.Lock` around `pipeline.run` (models are not thread-safe;
  CPU box anyway).
- `main()`: `uvicorn.run(create_app(), host=env, port=8000)`.
- Tests with TestClient + fake pipeline: health 200; count on a tiny PNG ->
  schema fields, no `debug` key when omitted; count with `debug=true` ->
  `debug` present with caveats; HEIF-free bad bytes -> 400; overlay -> JPEG
  magic bytes; missing/wrong `X-API-Key` -> 401 (see Task 5b).
- Commit: `✨ feat(serve): /health, /count, /overlay endpoints`.
